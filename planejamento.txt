# Planejamento: Portfolio 3D Interativo — JP Studio

> **Objetivo**: Criar um site portfolio 3D imersivo como *case* do próprio JP Studio, demonstrando capacidade técnica e estética. O foco é um **Hero 3D interativo** + navegação fluida, performático em mobile e desktop.

---

## 1. Conceito & Direção Criativa

### Tema: "Beleza em Movimento"
- **Metáfora visual**: Partículas/delgadas fibras que reagem ao cursor/scroll — remetem a cílios, fios de cabelo, cerdas de pincel, brilho de esmalte
- **Paleta**: Derivada do design system existente (vinho, dourado, carvão, nude) — tokens já definidos em `src/styles.css` / `tailwind.config`
- **Tom**: Elegante, tátil, premium — não "tech demo", mas experiência de marca

### Referências Visuais
| Referência | O que aproveitar |
|------------|------------------|
| **Rive.app / LottieFiles showcase** | Animações vetoriais leves, interativas |
| **Three.js Journey / Bruno Simon** | Scroll-driven 3D, performance mobile |
| **Apple product pages** | Reveal on scroll, parallax sutil, foco no produto |
| **Cílios macro photography** | Textura, transparência, reflexo — base para shaders |

## 2. Arquitetura Técnica

### Stack 3D
| Camada | Escolha | Justificativa |
|--------|---------|---------------|
| **Core** | **Three.js (r160+)** via `@react-three/fiber` (R3F) | Ecossistema React nativo, suspense, SSR-friendly |
| **Abstrações** | `@react-three/drei` | `Html`, `Text`, `ScrollControls`, `Effects`, `Environment` prontos |
| **Física/Partículas** | `three-gpu-pathtracer` ou custom compute shader | 10k+ partículas @ 60fps mobile via GPU |
| **Scroll** | `gsap` + `ScrollTrigger` (ou `@react-three/drei/ScrollControls`) | Scroll-driven timeline, scrub suave |
| **Carregamento** | `useGLTF` + `drei/Preload` + `React.Suspense` | Progressive loading, LCP protegido |
| **Build** | Vite (já configurado) + `vite-plugin-glsl` para shaders | HMR shaders, tree-shaking Three.js |

### 3.2 Sistema de Partículas (GPU Compute Shader)
```glsl
// particle.frag.glsl — fragment shader do compute pass
// Cada partícula: position (vec3), velocity (vec3), life (float), size (float)
// Uniforms: uTime, uMouse, uScroll, uAttractors[4], uNoiseTexture

void main() {
  vec3 pos = texture(positionTex, uv).rgb;
  vec3 vel = texture(velocityTex, uv).rgb;
  float life = texture(lifeTex, uv).r;

  // Atração por "pontos de beleza" (cílios, lábios, unhas)
  for (int i = 0; i < 4; i++) {
    vec3 attr = uAttractors[i];
    float dist = distance(pos, attr);
    float force = 1.0 / (dist * dist + 0.1);
    vel += normalize(attr - pos) * force * 0.02;
  }

  // Ruído curl para organicidade
  vec3 noise = curlNoise(pos * 0.5 + uTime * 0.1);
  vel += noise * 0.01;

  // Damping + integração
  vel *= 0.98;
  pos += vel * deltaTime;

  // Respawn se life <= 0
  if (life <= 0.0) { pos = randomSpherePoint(3.0); life = 1.0; }
  life -= deltaTime * 0.15;

  // Output para ping-pong textures
  gl_FragColor = vec4(pos, life); // positionTex
  // velocityTex, lifeTex escritos em passes separados
}
```

**Parâmetros ajustáveis (expostos no `useParticleSystem`):**
| Parâmetro | Default | Range | Afeta |
|-----------|---------|-------|-------|
| `count` | 15000 | 5k–50k | GPU load |
| `attractorStrength` | 0.02 | 0–0.1 | Intensidade atração |
| `noiseScale` | 0.5 | 0.1–2 | Turbulência |
| `lifeSpan` | 6.5s | 2–15s | Densidade visual |
| `baseSize` | 0.015 | 0.005–0.05 | Tela cheia vs sutil |

### 3.3 Interações
| Gatilho | Resposta | Implementação |
|---------|----------|---------------|
| **Mouse move** | Atractor segue cursor (suavizado 0.15s) | `useFrame` + `lerp` no `uAttractors[0]` |
| **Scroll** | Câmera desce + partículas "caem" + reveal conteúdo | `ScrollControls` ou GSAP timeline scrub |
| **Click/Tap** | Pulso radial (shockwave) no ponto | Compute shader: `vel += normalize(pos - clickPoint) * 0.5` |
| **Hover CTA** | Partículas convergem para botão | `uAttractors[1] = buttonWorldPosition` |
| **Resize** | Recalcula aspect, repositiona attractors | `useSize` hook + `camera.aspect = w/h` |

### 3.4 Scroll-Driven Narrative (Seções)
```typescript
// Timeline GSAP sincronizada com ScrollTrigger
const heroTimeline = gsap.timeline({
  scrollTrigger: {
    trigger: "#portfolio-canvas",
    start: "top top",
    end: "bottom top",
    scrub: 1,
```

```typescript
// src/portfolio/lib/case-schema.ts
import { z } from 'zod';

export const CaseCategorySchema = z.enum([
  'branding',
  'web',
  'mobile',
  'motion',
  '3d',
  'print',
  'photography',
  'other',

export const CaseTechSchema = z.object({
  name: z.string(),
  icon: z.string().optional(), // lucide icon name ou custom SVG
  color: z.string().optional(), // hex para badge
});

export const CaseAssetSchema = z.object({
  type: z.enum(['image', 'video', 'model3d', 'iframe', 'lottie']),
  src: z.string(),
  poster: z.string().optional(),
  alt: z.string(),
  width: z.number().optional(),
  height: z.number().optional(),
  // Para modelos 3D
  format: z.enum(['glb', 'gltf', 'usdz']).optional(),
  environment: z.string().optional(), // HDRI específico
  cameraPosition: z.tuple([z.number(), z.number(), z.number()]).optional(),
  cameraTarget: z.tuple([z.number(), z.number(), z.number()]).optional(),
});

export const CaseMetricSchema = z.object({
  label: z.string(),
  value: z.string(),
  description: z.string().optional(),
});

export const CaseSchema = z.object({
  // Identidade
  id: z.string().uuid(),                    // UUID v4
  slug: z.string().regex(/^[a-z0-9-]+$/),   // URL-friendly

  shortDescription: z.string().max(160),    // Card/SEO
  category: CaseCategorySchema,
  tags: z.array(z.string()).default([]),
  featured: z.boolean().default(false),     // Destaque no hero/grid
  order: z.number().int().default(0),       // Ordenação manual

  // Conteúdo rico
  cover: CaseAssetSchema,                   // Imagem/video principal do card
  gallery: z.array(CaseAssetSchema).min(1).max(20), // Carrossel no detail
  description: z.string(),                  // Markdown/HTML longo
  challenge: z.string().optional(),         // Desafio do projeto
  solution: z.string().optional(),          // Solução aplicada
  results: z.array(CaseMetricSchema).default([]), // KPIs/métricas

  // Técnico
  techStack: z.array(CaseTechSchema).default([]),
  role: z.string().optional(),              // Meu papel no projeto
  duration: z.string().optional(),          // Ex: "6 semanas"
  teamSize: z.number().int().optional(),

  // Links
  liveUrl: z.string().url().optional(),
  repoUrl: z.string().url().optional(),
  caseStudyUrl: z.string().url().optional(), // Artigo detalhado externo

  // Metadados
  clientName: z.string().optional(),
  clientLogo: z.string().optional(),        // URL logo cliente
  publishedAt: z.string().datetime(),       // ISO 8601
  updatedAt: z.string().datetime().optional(),
  status: z.enum(['published', 'draft', 'archived']).default('published'),

  // 3D Specific (opcional, para cases imersivos)
  scene3d: z.object({
    enabled: z.boolean().default(false),
    modelUrl: z.string().optional(),        // .glb da cena completa
    entryAnimation: z.enum(['flyIn', 'dissolve', 'scaleUp', 'none']).default('flyIn'),
    hotspots: z.array(z.object({
      position: z.tuple([z.number(), z.number(), z.number()]),
      title: z.string(),
      content: z.string(),                  // HTML/markdown
      type: z.enum(['info', 'video', 'image', 'link']).default('info'),
    })).default([]),
  }).optional(),
});

export type Case = z.infer<typeof CaseSchema>;
export type CaseAsset = z.infer<typeof CaseAssetSchema>;
export type CaseMetric = z.infer<typeof CaseMetricSchema>;
```

### 3.5.2 Fonte de Dados (CMS-Ready)
| Opção | Como funciona | Prós | Contras |
|-------|---------------|------|---------|
| **JSON estático** (`src/portfolio/data/cases.json`) | Array de `Case` no bundle | Zero deps, fast, versionado | Requer rebuild para adicionar |
| **Supabase (tabela `portfolio_cases`)** | Mesmo backend do agendamento | CMS real, admin panel, RLS, realtime | Mais complexo, latência |
| **Headless CMS (Contentful/Sanity/Strapi)** | API externa | Editor visual, webhooks, preview | Custo, dependência externa |
| **Arquivos MDX** (`content/cases/*.mdx`) | Frontmatter + Markdown | Git-based, preview local, tipado | Build step, menos flexível para assets 3D |

**Recomendação inicial**: **JSON estático + Supabase opcional** — comece com JSON (zero config, deploy automático), migre para Supabase quando a cliente quiser editar sozinha. O schema Zod valida ambos.

```typescript
// src/portfolio/lib/cases.ts
import { CaseSchema, type Case } from './case-schema';
import casesJson from './cases.json'; // ou fetch do Supabase

export async function getCases(): Promise<Case[]> {
  const parsed = CaseSchema.array().safeParse(casesJson);
  if (!parsed.success) {
    console.error('Invalid cases data:', parsed.error.flatten());
    return [];
  }
  return parsed.data
    .filter(c => c.status === 'published')
    .sort((a, b) => b.order - a.order || new Date(b.publishedAt).getTime() - new Date(a.publishedAt).getTime());
}

export async function getCase(slug: string): Promise<Case | null> {
  const cases = await getCases();
  return cases.find(c => c.slug === slug) ?? null;
}

export async function getFeaturedCases(limit = 3): Promise<Case[]> {
  const cases = await getCases();
  return cases.filter(c => c.featured).slice(0, limit);
}
```

### 3.5.5 Navegação Entre Cases (Fluid & 3D)
| Transição | Implementação |
|-----------|---------------|
| **Grid → Detail** | Shared Element Transition (View Transitions API) — cover image "voa" para hero do detail |
| **Detail → Detail (prev/next)** | Cross-fade + slide horizontal (GSAP FLIP) — mantém scroll position |
| **Detail → Grid** | Reverse shared element + particles "explodem" para posição do card |
| **Teclado** | `←` `→` navegam prev/next, `Esc` volta grid, `Tab` foco ordenado |
| **Touch** | Swipe horizontal no detail → prev/next (threshold 80px) |
| **URL** | History pushState — deep linkable, shareable, SEO-friendly |

- **Supabase Admin Panel**: Tabela `portfolio_cases` com RLS (só admin/editor)
- **Campos**: Todos do schema + `seo_title`, `seo_description`, `og_image`
- **Upload assets**: Supabase Storage bucket `portfolio-assets` (CDN, transform on-the-fly)

## 4. Performance & Qualidade Adaptativa

### 4.1 Orçamento de Frame (Target: 60fps / 16.6ms)
| Item | Budget Mobile | Budget Desktop |
|------|---------------|----------------|
| Particle compute (2 passes) | 4ms | 2ms |
| Render (scene + post) | 6ms | 3ms |
| React overhead | 2ms | 1ms |
| **Total** | **~12ms** | **~6ms** |
| **Margem** | **4.6ms** | **10.6ms** |

### 4.2 Auto-Quality (hook `usePerformance`)
```typescript
// Monitora FPS médio 2s → ajusta particleCount + post-process
const qualityTiers = [
  { name: 'ultra', count: 30000, bloom: true, chromatic: true, ssr: true },
  { name: 'high',  count: 20000, bloom: true, chromatic: false, ssr: false },
  { name: 'mid',   count: 12000, bloom: false, chromatic: false, ssr: false },
  { name: 'low',   count: 6000,  bloom: false, chromatic: false, ssr: false },
];

// Se FPS < 50 por 3s consecutivos → desce tier
// Se FPS > 58 por 10s → sobe tier (com hysteresis)
```

### 4.3 Fallbacks A11y
- `prefers-reduced-motion`: **desliga** partículas animadas → mostra imagem estática (WebP hero) + fade-in simples
- `prefers-contrast: more`: desliga bloom/chromatic, aumenta opacidade textos
- `low-end-device` (detectado via `navigator.deviceMemory < 4` ou `hardwareConcurrency < 4`): inicia no tier `low`

### 5.5 View Transitions API (Navegação Fluida)
```typescript
// src/portfolio/hooks/useViewTransition.ts
export function useViewTransition() {
  const [transitioning, setTransitioning] = useState(false);

  const navigateWithTransition = useCallback(
    async (href: string, element: HTMLElement) => {
      if (!document.startViewTransition) {
        window.location.href = href;
        return;
      }

      setTransitioning(true);
      const transition = document.startViewTransition(async () => {
        window.location.href = href;
      });

      // Aguarda a transição completar
      try {
        await transition.finished;
      } finally {
        setTransitioning(false);
      }
    },
    []
  );

  return { transitioning, navigateWithTransition };
}
```

## 7. Riscos & Mitigações

| Risco | Probabilidade | Impacto | Mitigação |
|-------|---------------|---------|-----------|
| Three.js bundle size > 150kb gzipped | Alta | LCP, mobile | `three-stdlib` tree-shaking, `import { Mesh } from 'three'` (não `three/src`), dynamic import da rota portfolio |
| Compute shader não roda em Safari iOS (WebGL2) | Média | Quebra hero | Fallback: `GPUComputeRenderer` → CPU fallback (menor count) ou `canvas 2d` partículas simplificadas |
| Memória GPU mobile (texture ping-pong 4×15k) | Média | Crash/tab reload | `rgba16float` ao invés `rgba32float`, `count` adaptativo via `usePerformance` |
| Scroll jank em mobile (GSAP + Three.js) | Alta | UX ruim | `ScrollControls` (native Three.js) ao invés GSAP, `passive: true` listeners, `will-change: transform` |
| Acessibilidade (screen readers) | Média | Legal/SEO | Camada HTML semântica paralela (`aria-hidden` no canvas), `prefers-reduced-motion` testado |
| **Cases com assets pesados (video/3D) → LCP/CLS** | Alta | Performance, UX | Lazy-load tudo abaixo do fold; `preload` só cover do case atual; `loading="lazy"` + `fetchpriority="low"`; placeholders blur (LQIP) |
| **View Transitions API não suportada (Firefox/Safari antigos)** | Média | Navegação menos fluida | Fallback GSAP FLIP animation — mesma sensação, sem API nativa |
| **Navegação teclado/touch entre cases quebra foco** | Média | A11y | `useCaseNavigation` gerencia `focus()` explícito; `tabIndex` controlado; testar com NVDA/VoiceOver |
| **JSON `cases.json` cresce > 500kb → bundle size** | Baixa | Build/LCP | Migrar para Supabase/Contentful quando > 50 cases; code-split por categoria |
| **Hotspots 3D em mobile (touch) — precisão baixa** | Média | UX | Hit-area aumentada (radius 2x); feedback visual + haptics (`navigator.vibrate`); fallback tooltip HTML |
